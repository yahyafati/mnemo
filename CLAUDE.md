# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

Mnemo is a local-first spaced-repetition Android app (package `com.yahyafati.mnemo`). Read `docs/PROJECT_OVERVIEW.md` (product), `docs/ARCHITECTURE.md` (modules, layers, rules) and `docs/ROADMAP.md` (phases). Decisions are recorded in `docs/adr/`.

**Phases 0–6 are implemented** (open: Phase 1's frame-rate exit check, Phase 3's manual "Test connection" against a real hosted and local provider, Phase 4's manual "1,000 words in under 30 s" check and on-device dictation, Phase 5's on-device frame-rate check of Analytics, and Phase 6's hardware checks in ADR 0008): decks (nested `Parent::Child`), manual Basic / Basic + Reversed / Cloze notes, FSRS-6 study sessions with undo, scheduling/appearance settings; Anki `.apkg`/`.colpkg` import and export, media (images, KaTeX math), backup/restore, JSON export and the card browser; AI providers (Settings › AI providers: presets, encrypted keys, test connection, per-task routing, token usage); Smart Extract (paste, PDF, link, dictation → streamed review queue → accepted notes) and study-time Explain / Example / Rewrite; Analytics (KPIs, forgetting curve, activity calendar, deck maturity, forecast, hardest cards), the Decks retention tiles and the on-device FSRS optimizer (Settings › Scheduling); Type-in and Multiple choice cards, hints, audio/TTS, exam countdowns, AI Co-Author, the daily reminder, the home-screen widget, onboarding, tablet/foldable layouts and R8 release builds. The license is GPL-3.0-or-later (`LICENSE`, `NOTICE`, ADR 0009): no proprietary SDKs, and new bundled or linked third-party code needs its notice added to `NOTICE`. Release docs (store listing, privacy policy, distribution, signing) are in `docs/release/`; the path to v1.0 on Play and F-Droid is `docs/release/ROADMAP.md`. A desktop app (Windows, macOS, Linux) from the same codebase via Compose Multiplatform is in progress: `docs/desktop/ROADMAP.md` (steps D0–D9 and the working rules that keep Android shippable meanwhile). D0–D7 are done (D8 is built, not yet run on GitHub; D9's runbook `docs/desktop/qa.md` is written and waits for the owner's pass on real machines): the technical choices and versions are in ADR 0010 (Koin, Compose Multiplatform 1.12.1 with Material3 pinned to 1.9.0, JLaTeXMath, KMP modules with AGP's `com.android.kotlin.multiplatform.library`), Koin has replaced Hilt on Android (see "Dependency injection" below), the Android APIs sit behind interfaces ("Platform seams") and the data layer is multiplatform: `:core:{database,datastore,security,ingest,data,domain,testing}` are KMP modules with an Android and a `desktop` (JVM) target (see "Kotlin Multiplatform modules" below), and so are `:core:designsystem` and `:core:ui` (D5: fonts, logo and strings in Compose resources; card math, images and sound on desktop), the six features and `:shell` (D6: the app shell, navigation and onboarding both launchers share). `:desktop` opens the collection (`openCollection`: single-instance lock, staged restore, Koin) and shows the same app as the phone in a window; the window's size and place come back, and the keyboard, menu bar, mouse and drag and drop are D7 ("Desktop experience" below), the installers and their release workflow D8 ("Desktop packaging and release" below).

**EPUB books** (chapter text is Markdown since web roadmap W5: `EpubReader` uses `MarkdownText`, and its stub/part thresholds count `MarkdownText.plain(text)`, the text without marks; in progress: B0–B6 done: `EpubReader` in `:core:ingest`, `SourceRepository.readBook` in `:core:data`, `CreateBookDecksUseCase` + `BookDeckNames` in `:core:domain`, ADR 0011, the import screen `BookImportRoute` / `BookImportViewModel` in `:feature:create`, reached from the Create tab's Smart Extract card and, on the desktop, by dropping or opening an `.epub`, and Smart Extract's EPUB source: pick a chapter, its text fills the box and its deck, found by computing its `BookDeckNames` path, is preselected; the import's "Generate cards" hands the parsed book over in memory through `BookHandoff`; B6, the book run: "Create decks and generate" confirms the number of requests and the provider, then Smart Extract goes through the chapters in order one review queue at a time, moving on only when the user presses Next, with `BookBatch` in its UI state, `BookHandoff.Offer.batch`/`deckIds`; B7, polish and QA, is open): import a book into one deck per chapter, empty at first, with AI card generation per chapter afterwards. The steps (B0–B7), the verified code it builds on and the rules (DRM, zip safety, deck naming) are in `docs/epub/ROADMAP.md`; deck names (`Book::01 Chapter`, padded to the whole book's chapter count) always come from `BookDeckNames`, and the use case reuses existing decks instead of calling `saveDeck` on them, which would overwrite their description and category; read it before touching ingest, Smart Extract or deck creation for this. Sizes of text (the numbers shown, `TextChunker`'s parts, the card estimate) are `WordCount` (`:core:model`): Han and kana count two to a word, because Japanese and Chinese have no spaces; the EPUB reader's own stub thresholds still count words between spaces.

**PDF pages and images** (planned, not started): page ranges and a bookmark chapter picker, AI transcription of scanned pages into the text box (Auto / Read pages with AI), cards from page images, and figures on cards. Steps P0–P8 and the verified code they build on are in `docs/pdf/ROADMAP.md`; the decisions (no page stitching, no on-device OCR, Android `PdfRenderer` and desktop PDFBox for rendering, images only to `vision` models after their own disclosure) are ADR 0014.

Modules today: `:app`, `:desktop`, `:shell`, `:core:{ai,anki,common,data,database,datastore,designsystem,domain,ingest,model,scheduler,security,sync,testing,ui}`, `:feature:{analytics,browse,create,decks,settings,study}`. Add new ones to `settings.gradle.kts`.

## Commands

Use the Gradle wrapper from the repo root:

```bash
./gradlew assembleDebug testDebugUnitTest lint   # the phase exit check
./gradlew installDebug                           # install on connected device/emulator
./gradlew connectedDebugAndroidTest              # instrumented tests, needs a device

# single unit test class / method
./gradlew :app:testDebugUnitTest --tests "com.yahyafati.mnemo.ui.MnemoAppNavigationTest"
./gradlew :core:common:test --tests "com.yahyafati.mnemo.core.common.result.MnemoResultTest"

# screenshot baselines (Roborazzi, committed next to the tests): every feature, the shell's onboarding and the
# design system on Android in <module>/src/androidHostTest/screenshots
./gradlew verifyRoborazziAndroidHostTest
./gradlew recordRoborazziAndroidHostTest   # after an intended visual change; compare with docs/design/ by eye
# or without a local build: label the PR `record-screenshots` (Android) / run "Record screenshots" (`.github/workflows/record-screenshots.yml`, desktop on macOS); it commits the PNGs to the branch

./gradlew assembleRelease        # R8-minified; keep rules in app/src/main/keepRules
```

Desktop (docs/desktop/ROADMAP.md, ADR 0010):

```bash
./gradlew :desktop:run                    # open the desktop window
./gradlew :desktop:test                   # DesktopAppTest (the whole app in a test window), the collection flow, NativeLibrariesTest: bundled SQLite, zstd and Skia load on this OS
./gradlew :desktop:createDistributable    # app image in desktop/build/compose/binaries (jlink runs on a JDK 21 toolchain)
./gradlew :desktop:packageDmg             # the installer of this system: packageMsi (needs WiX 3), packageDeb / packageRpm / packagePortable (Linux)
python3 scripts/desktop/smoke-test-app.py desktop/build/compose/binaries/main/app --open-file core/anki/src/test/resources/modern.apkg   # starts the image
python3 scripts/qa/desktop-checks.py --help   # D9: info, verify-sums, startup, import-time, counts, mock-ai (docs/desktop/qa.md)
```

A Kotlin Multiplatform module has no `testDebugUnitTest` (ADR 0010): its tests are `testAndroidHostTest` (Robolectric) and `desktopTest`, and its screenshots `verifyRoborazziAndroidHostTest` / `verifyRoborazziDesktop` (`recordRoborazzi…` to re-record). Only `:app` still has `testDebugUnitTest` (app tests on `TestMnemoApplication`). The desktop baselines (`:core:designsystem`, `:core:ui`, in `src/desktopTest/screenshots`) are recorded on macOS arm64; Skia's output and the speaker emoji differ on other systems, and a plain `desktopTest` doesn't compare them. The Android exit check is `./gradlew assembleDebug testDebugUnitTest testAndroidHostTest lint verifyRoborazziAndroidHostTest`; `.github/workflows/ci.yml` runs `desktopTest :desktop:test :core:anki:test` on Ubuntu, Windows and macOS.

`python3 scripts/desktop/check-android-imports.py` (CI job `android-imports`) fails on an Android import outside the Android-only files; `--list` shows every file that has one.

JVM modules (`:core:model`, `:core:common`, `:core:scheduler`, `:core:anki`, `:core:ai`, `:core:sync`) use `test`, not `testDebugUnitTest`, so run them too: `./gradlew :core:ai:test :core:anki:test :core:model:test :core:scheduler:test :core:common:test :core:sync:test`.

Anki test packages in `core/anki/src/test/resources/` are written by real Anki: regenerate with `core/anki/fixtures/make_fixtures.py` (needs `pip install anki`). Tests that depend on them check relationships, not absolute dates.

The Gradle configuration cache is on. `local.properties` is machine-specific.

## Build setup (non-obvious bits)

- **Convention plugins** in `build-logic/` (included build) hold all shared config: `mnemo.android.application` and `.compose` (`:app` only), `mnemo.jvm.library`, and for the multiplatform modules `mnemo.kmp.library` (Android + `desktop` targets), `mnemo.kmp.compose`, `mnemo.kmp.feature`, `mnemo.kmp.room` and `mnemo.desktop.application`. `mnemo.kmp.room` is Room through KSP on both targets with the schemas in the host tests' assets. The data-layer modules use `mnemo.kmp.library`; `:core:designsystem` and `:core:ui` add `mnemo.kmp.compose` (which also turns on the Android target's resources: without that, Compose resources are not packaged and Robolectric tests fail with "Missing resource"); the features and `:shell` apply `mnemo.kmp.feature` (library + compose + serialization + Roborazzi + Koin, navigation and lifecycle from the JetBrains artifacts, `:core:designsystem`, `:core:domain`, `:core:ui` in `commonMain`, `:core:testing` in `commonTest`). A module with Compose resources sets `compose.resources { packageOfResClass = … }`; a module with screenshot tests sets `roborazzi { outputDir … }` to `src/androidHostTest/screenshots` (copy a feature's build file). Add KMP dependencies to `getByName("commonMain").dependencies` (the typed `commonMain` accessor is not available in build-logic); in a module's own build file use `kotlin { sourceSets { commonMain.dependencies { … } } }`, and a dependency with an `exclude` goes through `dependencies { "androidMainImplementation"(dep) { exclude(…) } }` (see `:core:ingest`). Module build files should be a few lines; put shared settings in the plugins (`build-logic/convention/src/main/kotlin`).
- Library namespaces are derived from the module path (`:core:designsystem` → `com.yahyafati.mnemo.core.designsystem`). Don't set `namespace` in library modules.
- Features must never depend on other features. They navigate through the `@Serializable` routes in `:core:ui/navigation/Routes.kt`; only `:shell` depends on all of them. A feature's layout: `commonMain` (screens, ViewModels, `composeResources`), `commonTest` (ViewModel tests, run on both targets), `androidHostTest` (Compose UI and screenshot tests on Robolectric), and `desktopTest` when the desktop needs its own.
- **AGP 9.x with built-in Kotlin**: there is no `org.jetbrains.kotlin.android` plugin. Don't add it. Pure JVM modules use `org.jetbrains.kotlin.jvm` (via `mnemo.jvm.library`).
- Kotlin is pinned to 2.3.21 (KSP 2.3.x). Lint suggests 2.4.x. Upgrade Kotlin and KSP together (Room uses KSP) and rerun the build.
- The new AGP DSL is in use: `compileSdk { version = release(37) }`, and `buildTypes.release.optimization { enable = true }` (R8) instead of `isMinifyEnabled`.
- `compose_stability.conf` (root, applied by the Compose convention) marks `:core:model` and `java.time` types stable. Keep model classes immutable (`val`, read-only collections), or remove them from it.
- Screenshot tests capture to `src/androidHostTest/screenshots/<name>.png` (the path is in the test).
- R8 keep rules go in `app/src/main/keepRules/*.keep`. There is no `proguard-rules.pro`.
- minSdk 29, target/compileSdk 37, Java 11 bytecode.
- **Desktop packaging**: the Gradle daemon runs on the JDK 25 toolchain (`gradle-daemon-jvm.properties`), whose builds have no `jmods`, so `jlink` fails on it. `mnemo.desktop.application` points the JetBrains packaging tasks at a JDK 21 toolchain instead (lazily, so `:app` and F-Droid builds never need it). The runtime's modules are listed in that plugin (D8 trimmed them: what `:desktop:suggestRuntimeModules` finds plus what is loaded by name or service, see the comment there): re-run the suggestion after a dependency upgrade, and the smoke test below after changing the list. Compose Multiplatform artifacts use the catalog's `cmp-*` coordinates, not the deprecated `compose.runtime` accessors (`compose.desktop.currentOs` is the exception). Test with `runComposeUiTest` from `androidx.compose.ui.test.v2`.
- All dependencies and plugins live in `gradle/libs.versions.toml`. Compose artifacts take versions from the BOM, except `material-icons-extended`, which is no longer in the BOM.
- `settings.gradle.kts` uses `RepositoriesMode.FAIL_ON_PROJECT_REPOS`, so repositories go there, never in module build files. Type-safe project accessors are on (`projects.core.designsystem`).
- Unit tests run on the JDK 25 toolchain. The Android convention adds the `--add-opens`/`--add-exports` flags Robolectric needs, and turns off `failOnNoDiscoveredTests` for modules with no tests yet. Robolectric runs on SDK 36 (`src/test/resources/robolectric.properties`) because it doesn't ship 37.

## Release engineering (release ROADMAP R2)

- `mnemo.versionCode` / `mnemo.versionName` live in `gradle.properties` (bump `versionCode` for every upload). Release signing is `ReleaseConfig.kt` in `build-logic`: it reads `MNEMO_KEYSTORE_FILE`, `MNEMO_KEYSTORE_PASSWORD`, `MNEMO_KEY_ALIAS` (and optional `MNEMO_KEY_PASSWORD`) from the environment or `local.properties`, and falls back to an unsigned build. Never commit a keystore or its passwords; the routine is `docs/release/signing.md`.
- Direct distribution (`docs/release/sideload-roadmap.md`): the APK is signed with the owner's keystore, the same key for every update (Android refuses a changed signer). `python3 scripts/check-apk-signature.py [--cert-sha256 …] <apk>…` fails on an unsigned or debug-signed APK or a different signer; CI secrets and the tag ruleset are in `docs/release/signing.md`. The release APK is universal (all four ABIs, one file).
- The Open-source licenses screen is `LicensesScreen` (`:feature:settings`), fed a loader for the JSON that AboutLibraries generates (`licensesScreen(loadLibraries = …)`): in `:app` the raw resource `R.raw.aboutlibraries` (`MainActivity.loadLicenses`), in `:desktop` a classpath resource from the JVM plugin's `exportLibraryDefinitions` (`AppInfo.loadLicenses`). Bundled files Gradle doesn't know about (fonts, KaTeX, py-fsrs) and the license texts are JSON in `app/config/{libraries,licenses}`: add a file there when you bundle something new, and to `NOTICE`. The desktop list reuses `app/config` without KaTeX; what only the desktop bundles (the Java runtime) and the texts of its libraries' licenses are in `desktop/config`. Offline mode needs a text for every license id a dependency names, or the export warns. Don't add Google's `oss-licenses-plugin` or any Play Services/Firebase library (`LicensesFlowTest` fails on them).
- Every piece of AI output shows a Report button (`ReportAiButton`, `:core:ui/ai`): confirm dialog, then a prefilled GitHub issue in the browser. New AI surfaces need one. Links to the repo, issues, releases and policy are `ProjectLinks` (`:core:model`); Settings › About › Latest release only opens `RELEASES` in the browser, because the app makes no update check (sideload roadmap S5).
- Ask for a permission with `PermissionRationaleDialog` (`:core:ui/permission`) first, unless the toggle the user just flipped already explains it.
- F-Droid (R7, `docs/release/fdroid.md`): its texts, changelog and graphics are `fastlane/metadata/android/en-US/` (`scripts/fdroid/fastlane.py` checks it, `--sync` copies the graphics from `docs/release/assets`; every release needs `changelogs/<versionCode>.txt`). The recipe for `fdroiddata` is `docs/release/fdroid/com.yahyafati.mnemo.yml`, kept in `fdroid rewritemeta`'s canonical form. F-Droid's scanner rejects the foojay JDK-download plugin (the recipe's `prebuild` removes it, so keep it a single line in `settings.gradle.kts`) and the APK dependency-metadata block (`dependenciesInfo.includeInApk = false`). `scripts/fdroid/check-foss-deps.py` runs in CI.
- The download page (sideload roadmap S4) is `scripts/pages/{index.html,download.js,build.py}`, deployed by `pages.yml`; its file table must match the stable names in `scripts/release/prepare-release.py` (`build.py` checks). A new installer or a renamed file goes into both.
- Pre-launch QA (R3) is `docs/release/qa.md`: a runbook for the release build with a results log. `scripts/qa/device-checks.sh` wraps the `adb` parts (install-over, startup time, `gfxinfo` frame stats, airplane mode, `.apkg` push, mock AI server). Record results in the log, not in chat.
- `python3 scripts/check-16kb-alignment.py <aab|apk>` checks native libraries for 16 KB pages; CI (`.github/workflows/ci.yml`) runs it on the unsigned release build.

## Platform seams (desktop D3, ARCHITECTURE §4.3)

- Shared code (everything but `:app` and the `android` packages) must not import `android.*`, `androidx.work`, `androidx.activity`, `androidx.webkit`, `androidx.documentfile`, `androidx.core`, `LocalContext` or `AndroidView`. Put the API behind an interface and its Android implementation in a package named `android` (`AndroidXxx.kt`), in `androidMain` once the module is KMP (the desktop one is `DesktopXxx.kt` in `desktopMain`). The check script scans `commonMain`, `desktopMain` and `src/main` too; its `PENDING` list holds the `:app` launchers and only shrinks: a listed file with no Android import fails too, so delete its entry.
- Files and folders: `AppDirectories` (`files`, `cache`, `media`, `secrets`, `restoreStaging`, `databaseFile`, `dataStoreFile`) and `DocumentAccess` (`info`, `openInput`, `openOutput`, `delete`, folder create/list, `keepAccess`) are in `:core:common`; failures are `IOException`. Never use `Context.filesDir` or a `ContentResolver` in shared code. Tests use `FakeDocumentAccess` (`:core:testing/platform`) and `AndroidAppDirectories(context)` under Robolectric.
- Transfers: the work is in `ImportJob`/`ExportJob`/`BackupJob` (`:core:data/job`), which throw and report progress through a callback; the `*Worker`s map exceptions with `toTransferError()`, and own the notification, retries and `WorkKeys`. Media cleanup and the optimizer already are plain (`MediaRepository.collectGarbage`, `FsrsOptimization.run`), so their workers just call them.
- `PdfTextExtractor` and `SpeechTranscriber` are interfaces (`:core:ingest`). `SmartExtractUiState.dictationAvailable` comes from `SourceRepository.isDictationAvailable()`; the Dictation source is hidden without it or without the `dictation` capability.
- UI: read `LocalPlatformCapabilities` (never `Build.VERSION`), `LocalAppVersion`, `LocalUriHandler`, `rememberIs24HourFormat()`. Pick files with `rememberFilePicker`/`rememberMediaPicker`/`rememberFileSaver`/`rememberFolderPicker` (they report a location string, and nothing on cancel). Ask for permissions with `rememberPermissionRequest(AppPermission.…)`: use `canRequest` to decide whether to explain first, `isGranted` for state. `MnemoApp`'s host (`MainActivity`) provides the Android values, `ProvideDesktopPlatform` (`:core:ui/desktopMain`) the desktop ones, and `MnemoTheme` must be inside `LocalPlatformCapabilities`. The picker, permission and 24-hour functions are `expect`/`actual` (Android in `androidMain`, desktop: AWT dialogs, always granted, locale).
- Card math is `MathText` → `LocalMathRenderer` (Android: `KatexMathRenderer` in a WebView, assets in `core/ui/src/androidMain/assets/katex`, fonts read from the Compose resource assets; desktop: `JLaTeXMathRenderer` = `MarkdownText` with a `MathPainter`, which draws each formula to a bitmap; unprovided: raw TeX), images are `MediaImage` → `LocalMediaImageLoader` (Skia on desktop), sound is `LocalCardAudio` (`javax.sound` on desktop: wav, mp3, ogg). A new platform-specific renderer follows the same shape.
- Relative times use `RelativeAge` (`:feature:decks`), not `DateUtils`.
- **Sharing a deck** (Decks › deck menu › Share, Android only): `DeckShareRepository.prepare` (`:core:data`) writes the deck's `.apkg` (the same `AnkiExporter` as Export) to `cache/share/`, in-process and not as a transfer job, and `DecksViewModel.sharedDeckReady` hands it to the screen, which opens the share sheet with `rememberFileSharer` (`:core:ui/files`; `ACTION_SEND` through a `FileProvider` declared in `:app`'s manifest, whose `res/xml/share_paths.xml` allows only `cache/share/`; `ShareDeckProviderTest` pins the two). The item is hidden unless `PlatformCapabilities.shareFiles` (off on the desktop, whose Export already saves a file). There is no receiving side: Mnemo has no `.apkg` intent filter on Android, so a recipient imports through Import.

## Desktop experience (D7, ADR 0010)

- `PlatformCapabilities.keyboardAndMouse` (off unless provided; the desktop turns it on) says whether to *advertise* keys, tooltips, right-click menus and drop targets. The key handlers work everywhere (a tablet with a keyboard uses them), but the hints, `MnemoIconButton`'s tooltip and the shell's focus grabbing check it, so the phone's screens and screenshots don't change.
- **Shortcuts** are in `Shortcuts` (`:core:ui/keyboard`): a `Shortcut` is either a key with modifiers (`primary` = ⌘ on macOS and Ctrl elsewhere, matched when the key goes down with exactly those modifiers) or a *typed character* (Space, `1`, `e`, `?`). A focused text field leaves the key going down and up for its parents but consumes the typed character, so a plain-character shortcut must be a typed one or typing "e" in an answer would fire it (and a typed character never happens on a phone). Screens attach them with `Modifier.shortcuts(Shortcuts.X does { … })` (after the focused child) or `previewShortcuts` (before it: Ctrl+Enter in the editor). A text field inside something clickable (the study card) gets `consumeTypingKeys()` on the desktop: a clickable takes Space and Enter going down as a click. A new shortcut goes into `Shortcuts`, the `?` sheet (`ShortcutsDialog`, `:shell`) and, if it is a menu item, `DesktopMenu.kt`. A screen that wants the keys takes the focus itself (`focusRequester` + `focusable()`, and again when what it shows changes); a `FocusRequester` inside a `Scaffold`'s content is asked from inside that content.
- **Commands.** Menu items, global shortcuts and dropped files are `AppCommand`s sent to `AppCommands` (`:shell`), carried out by `MnemoRoot` (navigation, file dialogs through the shared pickers, `MainViewModel` for import, backup, export and restore). The desktop window creates the `AppCommands`, and `DesktopApp(commands = …)` hands it to the shell; tests send commands directly. `globalShortcuts(commands)` is also passed to `Window(onKeyEvent)` for keys that arrive while nothing has the focus.
- **Menus hold no editing commands** (Undo, Cut, Copy, Paste): macOS's menu bar would take ⌘Z and friends from text fields.
- Icon buttons are `MnemoIconButton` (`:core:designsystem`: `icon` + `contentDescription`, optional `shortcut` label; tooltip on the desktop), not `IconButton`. Mnemo's clickable surfaces get `clickCursor()`. Right-click menus are `ContextMenuHost(actions) { … }` with the entries the overflow button already has; scrollbars `ScrollbarBox(state) { … }` / `ScrollbarFor(state)`; drops `Modifier.fileDropTarget(accepts, onHover, onDrop)` (`:core:ui`; `expect`, the Android actuals add nothing). Screens whose body should stop growing on a big window use `Modifier.readingWidth()` (`LocalMaxContentWidth`, set by the shell: 1,100 dp on the desktop).
- The window: `desktop/.../WindowPlacement.kt` (`window.properties` in the data directory, minimum size 720 × 520), `DesktopMenu.kt`, `DesktopIntegration.kt` (macOS About / Settings / Quit / open files, Dock icon). Icons: `python3 docs/release/assets/generate_desktop_icons.py` (needs `rsvg-convert`) writes the window icon (`desktop/src/main/resources/icons`) and the installers' (`desktop/icons`).

## Desktop packaging and release (D8, ADR 0010)

- `mnemo.desktop.application` holds the installer settings: `.dmg` (bundle id `com.yahyafati.mnemo.desktop`, one per architecture: Apple Silicon on `macos-latest`, Intel on `macos-15-intel`, both ad-hoc signed by jpackage), `.msi` (per user, installed under `%LOCALAPPDATA%\Programs\Mnemo` because `%LOCALAPPDATA%\Mnemo` is the collection, `upgradeUuid` fixed forever), `.deb`/`.rpm` (package name `mnemo`, `/opt/mnemo`) and the `.apkg`/`.colpkg` file associations. `LICENSE` and `NOTICE` ship in the app's `resources/` (`copyLicenseTexts`), not as jpackage's `licenseFile`, which would make the installers ask people to accept the GPL. jpackage cannot cross-build: each format is built on its own OS (`:desktop:package<Format>`; the tasks exist everywhere and fail on the wrong one). `:desktop:packagePortable` is the Linux `.tar.gz` of the app image. `packageVersion` is `mnemo.versionName`, which must stay `MAJOR.MINOR.PATCH` (jpackage rejects a suffix; macOS needs a major version of at least 1).
- jpackage copies every icon into the app by file name, so a file association's icon can't be the app icon's file: `desktop/icons/mnemo-package.*` are copies made by `generate_desktop_icons.py`.
- Windows and Linux start the program with a file's path as an argument; macOS calls `Desktop.setOpenFileHandler`. A second process can't open the collection, so `Main.kt` leaves the paths in `<data>/open-requests/` (`OpenRequests`) and exits 0; the running window polls every half second, opens them as `AppCommand.OpenFile` and comes to the front. Requests older than a minute are dropped.
- `scripts/desktop/smoke-test-app.py` starts the packaged image on a scratch `MNEMO_DATA_DIR` (database created, still running, no class or library error, a file handed over by a second launch); `.github/workflows/release.yml` runs it on each OS before naming the installers. That workflow (tag `v*`, or by hand to only build) is the whole release (sideload roadmap S2): the `android` job builds the APK signed from the `MNEMO_*` Actions secrets and fails on a tag without them, the `package` matrix builds the installers, and one `release` job runs `scripts/release/prepare-release.py` (stable-name copies such as `Mnemo-android.apk`, one `SHA256SUMS.txt`, notes from `docs/release/release-notes.md` + the versionCode's F-Droid changelog; add `changelogs/<versionCode>.txt` for every release) and drafts the release. It is not proved on GitHub until its first run.
- QA (D9): `docs/desktop/qa.md` is the runbook and results log for the installers on each OS; `scripts/qa/desktop-checks.py` does its machine-checkable parts and `scripts/qa/make-large-apkg.py` (needs `pip install anki`) writes a 12,000-card package for the import check. Release day (tag, draft, publish) is at the end of that file.
- User docs: `docs/desktop/install.md` (download, unsigned-installer warnings, data locations, update, uninstall, moving a collection).

## Data and scheduling

- Layers follow ARCHITECTURE §2: Room (`:core:database`) and DataStore (`:core:datastore`) are only seen by `:core:data`, whose repositories (`*Repository` interfaces, `Offline*` implementations) map entities to `:core:model` types. Use cases live in `:core:domain`.
- `:core:scheduler` is a pure-Kotlin port of py-fsrs 6 with its own `Fsrs*` types (it may not depend on `:core:model`). `FsrsTest` holds the reference vectors; keep it in sync if the port changes. `StudyScheduler` (`:core:domain`) maps model cards to it and seeds fuzz per card, so previews equal saved answers.
- Room schema is exported to `core/database/schemas/` (currently v7). A schema change needs a version bump, a migration in `migration/Migrations.kt` (on `SQLiteConnection`: `connection.execSQL(…)`, statements with arguments through `prepare`/`bindText`; SQL must match the generated schema JSON), a `MigrationTest` case (shared: it runs on Robolectric in `testAndroidHostTest` and on desktop in `desktopTest`) and a fixture database of the new version in `core/database/src/commonTest/resources/fixtures` for `FixtureDatabasesTest`. Never enable destructive migration. Room uses the driver API on both targets: `RoomRawQuery` for raw queries, `useWriterConnection { it.immediateTransaction { … } }` for transactions (`TransactionRunner`), `MnemoDatabase.build(context)` on Android (`AndroidSQLiteDriver`, import `com.yahyafati.mnemo.core.database.android.build`) and `build(file)` on desktop (`BundledSQLiteDriver`). `AndroidSQLiteDriver` can't run `EXPLAIN`, and a closed database throws `CancellationException`.
- Rows use UUID ids, epoch-millis timestamps and soft deletes (`deletedAt`); every query filters `deletedAt IS NULL`. That includes `review_logs`: Undo soft-deletes the log (`ReviewLogDao.softDelete`), so a new query on that table must filter too.
- **Recording changes for sync** (docs/sync/ROADMAP.md S1, ADR 0013; the merge engine is S3, the lifecycle and the UI come in S4–S5): SQLite triggers on `decks`, `note_types`, `notes`, `cards`, `review_logs`, `media` and `ai_answers` fill the `sync_changes` outbox (`tbl`, `rowId` (a composite key joins its parts with `/`), `fields`: `*` for an insert, else the changed column names, comma-separated; `createdAt`/`updatedAt` are never listed), but only while `sync_state.enabled = 1 AND applying = 0` (`SyncDao.setEnabled`/`setApplying`). The triggers are generated from `SYNCED_TABLES` (`core/database/.../sync/SyncTriggers.kt`) and installed by `Migration5To6` and by `SyncSetup.onCreate`; **a column added to a synced entity must be added to that list too** (`SyncTriggersTest.everyColumnOfASyncedTableIsTrackedOrIsBookkeeping` fails otherwise), and a schema change that rebuilds a synced table must recreate its triggers. Write new synced data with `@Insert`/`@Upsert`/`UPDATE` (never `REPLACE`, which would skip the update trigger). `sync_state` (one row: `deviceId`, `clock`, `enabled`, `applying`) is created by `SyncSetup.onOpen` if missing; `PendingRestore` keeps the restoring device's id and turns sync off. `SyncClock` (`:core:data/sync`) is the hybrid logical clock. `review_logs` also records the schedule each answer produced (`stateAfter`, `stepAfter`, `dueAfter`, `repsAfter`, `lapsesAfter`; null for Anki imports and rows from before v6).
- **Sync format and stores** (docs/sync/ROADMAP.md S2, ADR 0013; the merge engine in `:core:data/sync` drives it): `:core:sync` is a pure JVM module (depends on `:core:common`, and `:core:model` for WebDAV's address rule; no Room, no Android) that knows the remote layout and nothing about the collection. `SyncStore` (`list(prefix)`, `read`, `write` for new files only, `overwrite` for a device's own `device.json`, `delete`; blocking; failures are the sealed `SyncException`: offline, auth, quota, not found, already exists, I/O, plus corrupt, unsupported version and passphrase from the format layer) is what a backend implements: `FolderSyncStore` (on `DocumentAccess`, which lists no subfolders, so the layout is flattened into one folder with `/` as `__`) and `InMemorySyncStore` (in the module's main source, so every module's sync tests can use it) exist, and so do `GoogleDriveSyncStore` (S6) and `WebDavSyncStore` (S7). Paths come from `SyncPaths` (never build one by hand; a path has no `__`, which is how the flat stores recover it). `SyncRemote` is the typed view the merge engine uses: `create` / `open` / `openWithKey`, `writeChanges` (splits a big list into files of about 2 MB, numbered from a `firstSeq`), `readChanges`, `writeDevice` / `readDevice`, snapshots and media as opaque bytes. Every file but `sync.json` is `FileCodec`'s envelope: `MNSY`, format version, flags, length, body, SHA-256; the body is zstd-compressed (not media) and, in an encrypted location, AES-256-GCM sealed with the file's path as associated data. A reader **ignores** a file that throws `SyncCorruptException` (`maybeIncomplete` = shorter than its header says: probably still being written, so stop at it for that device and retry next sync) and never rewrites a file of a newer version. The passphrase goes through NFKC, UTF-8 and hex before PBKDF2-HMAC-SHA256 (600,000 iterations, stored in `sync.json`), so providers that read password characters differently derive one key; only the derived key (`SyncKey.toBytes`) is kept, in `SecretStore`. Tests use `InMemorySyncStore` and a temporary directory (`DirectoryDocumentAccess`, in the module's tests: `:core:testing` depends on `:core:data`, which depends on `:core:sync`), never a network.
- **Sync merge engine** (docs/sync/ROADMAP.md S3, ADR 0013 "As built (S3)"; the lifecycle, background runs and UI come in S4–S5): `SyncEngine.sync(remote, device, announceSettings)` in `:core:data/sync` is one round (pack the outbox, read and apply the other devices' files in one transaction with `applying` set, pack the merge's own result, write `device.json`, fetch media); it takes no lock and decides nothing about when to run (S4's `SyncRepository`) and needs `sync_state.enabled = 1`. Pieces: `SyncPacker` (outbox → `Change.Put`s, one `SyncClock` value per run, media uploaded first), `SyncApplier` (per-field last writer by `(clock, device)`; `createdAt` earliest, `deletedAt` earliest non-null; a card's schedule is one unit; a note's `fields` merge by position with a hash baseline; edits that arrive before their row are kept in `sync_field_clocks.value`; a field with an unsent local change is left alone), `CardReconciler` (replays reviews that two devices gave one card, from the logs' `repsAfter` chain; the result is an ordinary local write), `SyncFixups` (merge same-name decks, delete cards of deleted notes, move work in a deleted deck to `<name> (recovered)`), `SchedulingSettings` (the settings record), `SyncMediaFiles`. Raw JSON row access to the synced tables is `SyncRows` (`:core:database/sync`, from `SYNCED_TABLES`). Bookkeeping is local and never synced: `sync_field_clocks` (stamps; `*` is a whole row; `fields#<i>` a note's text with its `base` hash) and `sync_seqs` (newest file applied per device, plus `gaps`, late files still awaited). **A new synced column or table needs its merge rule in `SyncSchema`** (a column in `SYNCED_TABLES` is merged per field by default; a list or a unit that must stay together needs a rule like the schedule's or `NoteFields`). `:core:data` can't see `StudyScheduler`, so `ScheduleReplayer` is bound in `domainModule` (`StudySchedulerReplayer`). Tests: `SyncMergeTest` (scenarios, two `SyncDevice`s with their own database and clock on one `InMemorySyncStore`), `SyncConvergenceTest` (random operations on 2 and 3 devices, `MNEMO_SYNC_SEEDS=250` for more seeds; compares `SyncDevice.dump()`). Known limit: an answer given on top of one that another device undid before syncing keeps the schedule computed on top of it.
- **Sync lifecycle** (docs/sync/ROADMAP.md S4, ADR 0013 "As built (S4)"; the Settings screen is S5): `SyncRepository` (`:core:data/sync`, `DefaultSyncRepository`, a Koin `single` with one mutex) wraps `SyncEngine` in create, join, rejoin, leave, delete, unlock, `uploadAsNew` and `syncNow`, and exposes `status` (`SyncStatus`: Off, Restored, Idle, Syncing, WaitingForNetwork, Error(`SyncProblem`)). The location is a `SyncBackend` opened by `SyncStores` (add a backend's case there); it is remembered in `<files>/sync/config.json` (`SyncConfigStore`, deliberately not in the database or preferences, so a restore keeps it) and the passphrase's key is `SecretIds.SYNC_KEY` in `SecretStore` (a new non-provider secret id must go into `SecretIds.RESERVED`, or `pruneOrphanedKeys` deletes it). `sync_state.enabled` plus the config give the states; a config with `enabled = 0` is `Restored`. Snapshots (`SyncSnapshots`: JSON lines of rows and **stamps** and the writer's positions) and clean-up (`SyncMaintenance`, `SyncPolicy`) are in `SyncMaintenance.kt`: a change file is deleted only when the newest snapshot (announced in its writer's `device.json`) covers it and every device seen in 90 days has applied it, and a device with no readable `device.json` stops the clean-up. A join writes its own `device.json` *before* it changes anything and reads its own old files once (`SyncEngine.sync(includeOwn = true)`). A new synced thing a snapshot must carry goes in `SyncSnapshots`. `SyncAutomation` (started by `MnemoApplication` and `openCollection`) syncs on start, 5 s after the last edit and, with `SyncBackgroundWork` (`SyncWorker` periodic on Android, a timer on the desktop), periodically. Tests: `SyncLifecycleTest`; `FakeSyncRepository` is in `:core:testing`.
- **Sync screen** (docs/sync/ROADMAP.md S5, ADR 0013 "As built (S5)"; Drive and WebDAV are in the next two entries): Settings › Sync is `SyncRoute` → `SyncScreen` / `SyncViewModel` / `SyncDialogs` in `:feature:settings/sync`, reached from `SyncSection` in Settings, the Decks banner (`SyncBanner`, shown for `SyncStatus.attentionFrom()` only) and "Sync now" while sync is off. `SyncRepository.inspect` / `isEncrypted` / `devices` are what the screen reads; `Throwable.syncProblem()` maps any failure to a `SyncProblem` (a new problem needs its text in `syncProblemText`, in the Decks banner and in `attentionFrom`). Never put a passphrase in the UI state or `SavedStateHandle`. "Sync now" is `AppCommand.SyncNow` / `Shortcuts.SyncNow` / File › Sync now. A new backend adds a `SyncBackend` case, its `SyncStores` branch, its setup dialog and its label in `folderLabel`.
- **Google Drive sync** (docs/sync/ROADMAP.md S6, ADR 0013 "As built (S6)"; WebDAV is the next entry): `GoogleDriveSyncStore` (`:core:sync/google`, OkHttp, app-data folder only, `appProperties.g` groups, resumable above 5 MB; take its base URLs from `GoogleEndpoints` so tests use MockWebServer, and test a change with `FakeDriveServer` + the `SyncStoreContract`), `GoogleOAuth` / `GoogleSignIn` (PKCE, `state` check, scope `drive.appdata` only: don't add `email`) and `GoogleAccessTokens`. The platform half of sign-in is the `OAuthAuthorizer` seam: `AndroidOAuthAuthorizer` + `OAuthRedirectHub` (`:core:data/androidMain`) with `OAuthRedirectActivity` in `:app` (redirect `<package>:/oauth2redirect`), `DesktopOAuthAuthorizer` (loopback `ServerSocket`). `GoogleDriveAccess` (`:core:data/sync`, behind `SyncStores`) keeps the refresh token as `SecretIds.GOOGLE_REFRESH_TOKEN` and signs out on `release` (leave, delete). `SyncBackend.GoogleDrive` has no fields; `SyncRepository.googleDriveAvailable` is false in a build without a Google client, and then the Sync screen hides the option. The client ids are build settings, never committed (`MNEMO_GOOGLE_CLIENT_ID` → `BuildConfig`, `MNEMO_GOOGLE_DESKTOP_CLIENT_ID`/`_SECRET` → `mnemo-google.properties`; `docs/sync/google-setup.md`), bound through `GoogleClientConfigSource` by `:app` and `:desktop`. A new problem or backend needs its wording in `syncProblemText`, the Decks banner and (for Drive) the `_drive` strings. Nothing has run against real Google yet (owner's pass, `docs/sync/qa.md` §7).
- **WebDAV sync** (docs/sync/ROADMAP.md S7, ADR 0013 "As built (S7)"): `WebDavSyncStore` (`:core:sync/webdav`, OkHttp, Basic auth, flat layout in the one folder the user names, `PUT` + `If-None-Match: *` is the claim on a new name, no redirects followed, `429`/`503` retried; its address is a constructor parameter so tests use MockWebServer: extend `FakeWebDavServer` and run the `SyncStoreContract`). `WebDavUrl` is the address rule (`AiEndpoint.check(url, isLocal = true)`, no user info or query: don't loosen it; the form uses `WebDavAddress`), and `WebDavMultistatus` reads a `PROPFIND` answer with strict patterns instead of an XML parser (keep it that way: no doctype or entity handling). `SyncBackend.WebDav(url, username)` is remembered in the config; the password is `SecretIds.WEBDAV_PASSWORD` (reserved) in `SecretStore`, owned by `WebDavAccess` (`test` changes nothing, `connect` makes the folder and keeps the password only after the server accepted it, `forget` on release); one password per device, so `SyncBackend.sharesAccessWith` stops a join from releasing the credential it just set. `SyncRepository.testWebDav` / `connectWebDav` / `updateWebDavPassword` are what the Sync form calls; a form's password is never in the UI state or `SavedStateHandle`. The store never makes the folder while syncing. Nothing has run against a real Nextcloud yet (owner's pass, `docs/sync/qa.md` §8).
- **Sync QA and help** (docs/sync/ROADMAP.md S8, ADR 0013 "As built (S8)"): `docs/sync/qa.md` is the runbook and results log for the owner's pass on real hardware (the S3 scenarios by hand, clocks, interrupted syncs, large collections, battery and data use, Drive, WebDAV, privacy); `docs/sync/help.md` is the user page (set-up, status messages, forgotten passphrase, restore, new phone), linked from `docs/desktop/install.md`: keep its button names equal to the strings in `:feature:settings`. `scripts/qa/sync-checks.py` has `folder` (every file's envelope length and checksum, devices' seq ranges), `compare` (two data folders) and `watch`; `scripts/qa/device-checks.sh` gained `battery`, `data` and `sync-work` (written, not yet run on a phone). `MNEMO_SYNC_SEEDS=1000 ./gradlew :core:data:cleanDesktopTest :core:data:desktopTest --tests "*SyncConvergenceTest*"` runs more random histories (the env var is not a Gradle input, so clean the test task or it is skipped as up to date). F-Droid builds have no Google client id, so Drive is hidden there and the recipe has no sync anti-feature.
- Time goes through `Clock`; "today" is `StudyDay` (rolls over at 4 a.m. local, like Anki).
- The study loop is optimistic: `StudyViewModel` computes the answer, shows the next card, then saves through a `Mutex` so saves and undos stay in order.
- Card text is a Markdown subset plus Anki cloze, images (`![](media:<sha256>)`), math (`\(…\)`, `\[…\]`, `$$…$$`) and `[sound:…]`. The parser and HTML renderer are in `:core:model/markdown` (shared with `:core:anki`); `:core:ui/card` renders natively, or, for cards with math, through a KaTeX WebView on Android and natively with JLaTeXMath pictures on desktop (ADR 0002, 0004, 0010). Cloze parsing is `Cloze` in `:core:model`.
- Media is content-addressed in `filesDir/media/<sha256>` (`MediaRepository`); `MediaEntity.id` is the hash, not a UUID. Garbage collection keeps anything younger than a day.
- Anki interop is ADR 0003. `:core:anki` is JVM-only: SQLite through the `androidx.sqlite` driver API (`AndroidSQLiteDriver` in the app, `BundledSQLiteDriver` in its tests) and zstd through `zstd-kmp`. Android-module Robolectric tests can't load zstd's Android natives, so `:core:data`'s build extracts the host's native from `zstd-kmp-jvm` onto the test library path.
- Long transfers (import, export, backup, media cleanup) are WorkManager workers in `:core:data/androidMain/work`, registered with `workerOf` in `workModule`; `MnemoApplication` is the `Configuration.Provider` and installs `KoinWorkerFactory` (the default initializer is removed in the manifest). On desktop the same jobs run on `TransferQueue`s in an application scope (`DesktopDataTransferRepository`; media cleanup weekly and the automatic backup daily, checked at start and hourly). UIs observe both via `DataTransferRepository`. App tests replace the `WorkManager` definition with a test one (`testStorageModule`).
- Restore is applied at startup by `PendingRestore.applyIfPresent`, before Koin creates the database or DataStore (they are built on first use, after `startKoin`); on desktop `openCollection` (`:desktop`) does it after taking the `SingleInstanceLock`. `restartToRestore()` restarts the process (`restartAndroidApp`, `ProcessAppRestarter`).

## Dependency injection (Koin 4, ADR 0010)

- Each module that has bindings exposes a public `xxxModule` (`commonModule`, `databaseModule`, `dataStoreModule`, `securityModule`, `dataModule` + `androidDataModule` + `workModule` (Android) or `desktopDataModule` (desktop), `domainModule`, one per feature, `shellModule` for `MainViewModel`). `:core:data` lists the data-layer ones in the `expect val dataLayerModules`; `:app`'s `mnemoModules` (`di/AppModules.kt`, plus the widget's `appModule`) is the whole graph, and `MnemoApplication` starts it with `androidContext`; `:desktop`'s `desktopModules` is the desktop one (keep the two lists in step when you add a module). Singles that hold files (the database, DataStore's scope, the desktop job scope) are closed with `onClose` (`org.koin.dsl.onClose`), so a restart or a test can reopen the same files. Classes carry no DI annotations: `factoryOf(::X) bind Y::class`, `viewModelOf(::XViewModel)`, `workerOf(::XWorker)`.
- Hilt's unscoped bindings are `factory`, `@Singleton` ones are `single` (database, DataStore, cipher, secret store, OkHttp client, PdfTextExtractor, WorkManager). Keep it that way unless a class needs sharing.
- A class that needs a dispatcher gets it in a lambda definition: `factory { X(get(), dispatcher(MnemoDispatchers.IO)) }` (`dispatcher` is in `:core:common/di`). `factoryOf` can't pass qualifiers.
- Screens get ViewModels with `koinViewModel()`; navigation arguments arrive in the `SavedStateHandle` as before. The widget provider is a `KoinComponent`.
- Later modules override earlier ones, which is how app tests swap the database, preferences, WorkManager and cipher: `TestMnemoApplication` starts `mnemoModules + testStorageModule`.
- `DependencyGraphTest` (`:app`) is the replacement for Hilt's compile-time check: `verify()` plus `checkModules`. When you add a ViewModel that reads a `SavedStateHandle` or a worker, add its class name to the lists in that test, or it fails with a missing parameter.

## Card types, reminders, widget (ADR 0008)

## AI providers (ADR 0005)

- `:core:ai` (JVM) is the only client for AI providers (`:core:ingest` fetches links and `:core:sync` talks to Drive and WebDAV, each with its own OkHttp use): `OpenAiCompatibleClient` (OkHttp, SSE via `okhttp-sse`) and `ConnectionProbe` (test connection + capability detection). Tests use MockWebServer, which runs on plain-HTTP localhost, so their configs set `isLocal = true`.
- API keys are never in Room. `SecretStore` (`:core:security`) keeps them AES-GCM-encrypted with a Keystore key in `noBackupFilesDir/secrets` (on desktop: the OS keychain holds the key and the files are in `<data>/secrets`), so backups/exports can't contain them. Never add a key column, log a key, or put one in `SavedStateHandle`. Robolectric has no Keystore: tests use `SoftwareSecretCipher`, and app tests replace the `SecretCipher` definition (`testStorageModule`).
- Plain HTTP only for providers marked local whose host is a local address (`AiEndpoint.check`, enforced again in the client). The network security config can't express LAN ranges, so the rule lives in code. The OkHttp client never follows redirects.
- `AiProviderRepository.routeFor(task)` → the task's route or the default provider (first enabled one with a model), or null. Every AI entry point shows `AiSetupPrompt` (`:core:ui/ai`) when it's null, and `AiDisclosureDialog` before the first request to a provider.
- Presets and URL rules are in `:core:model` (`AiProviderPresets`, `AiEndpoint`) because the settings UI needs them and features can't see `:core:ai`.

## AI creation (ADR 0006)

- **Web extraction** (ADR 0012, `docs/web/ROADMAP.md`; W0–W7 done except the owner's QA pass on real links): a link goes `WebPageExtractor` → the first `SiteExtractor` (`handles(url)` from the URL alone) whose `extract(url, fetcher)` returns non-null, else `GenericExtractor` (jsoup; `ContentFinder` scores the blocks Readability-style, falling back to the longest `article`/`main` element or the body; `MarkdownText`; a page with three or more headings gets them as sections through `MarkdownSections`). A site's failure is returned as is; null falls through. Every request goes through `PageFetcher` (redirects, 30 s, `MAX_BYTES`, User-Agent `Mnemo (+repo URL)`); a site finishes with `PageText.markdown(raw, title)` (`MAX_CHARS`, `NoText`). Sites are plain classes with their base URL as a constructor parameter, built in `dataModule`'s `sites` list; they may only contact the host typed or that site's own API host. `WikipediaExtractor` (`ingest/site/`) reads `/wiki/<Title>` and `index.php?title=` links on `<lang>[.m].wikipedia.org` through the REST API (one request; the title as one encoded path segment; `Special:`/`Media:` links fail with `SourceProblem.NotAnArticle` without a request; other namespaces, old revisions and non-view actions are left to the generic extractor), and `WikipediaArticle` strips references, infobox, navboxes, hatnotes, images and the end matter (by English title, or by structure: a section with only links or nothing) and keeps the sections as ranges of the text, which reach Smart Extract as `SourceText.sections` (`SourceSection`, identified by position and title); a disambiguation page keeps its lists and sets `SourceText.disambiguation` (a hint in Smart Extract). Smart Extract's Link source shows a "Choose sections" picker for a page with two or more, rewrites the box from the chosen ones (`SourceSections.join`, asking first if the user edited it) and preselects the section, with its subsections, that a `#Fragment` in the link names (`SourceSections.forFragment`). Read the "Adding a site extractor" checklist in the roadmap before writing one.
- Smart Extract: `SourceRepository` (`:core:ingest`: PdfBox-Android, OkHttp + jsoup, `SpeechRecognizer`) fills one editable text box → `GenerateCardsUseCase` splits it (`TextChunker`, ≤ 1,200 words per request) and runs the parts in order through `CardGenerationRepository` → `CardGenerationClient` (`:core:ai`). Nothing is saved until `AcceptGeneratedCardsUseCase` (one transaction, `source = AI`).
- `:core:ingest` has no DI library: its classes are plain constructors built in `:core:data`'s `dataModule`, like the AI client. PdfBox's BouncyCastle dependency is excluded on purpose (see the ADR); its tests need `isIncludeAndroidResources` for PdfBox's assets.
- Output format: `GeneratedCardsSchema` (`{"cards": [{type, front, back, tags}]}`), sent as `response_format` only if the model has `jsonOutput`, and always spelled out in the prompt. `ChatTextRunner` drops a feature the server rejects (schema, `stream_options`, streaming) before any text arrived; auth/429 errors are never retried.
- `GeneratedCardParser` is incremental and tolerant; `JsonRepair` runs even on valid JSON (LaTeX like `\frac` is valid JSON for a form feed). New malformed-reply cases go in `core/ai/src/test/resources/replies` with an expected count in `GeneratedCardParserTest`.
- Only the source text and the queue's fronts are sent; the deck's notes are deduplicated locally (`GeneratedCardValidator.key`). Keep it that way: the disclosure text says so.
- Co-Author (`:feature:create/coauthor`, `CoAuthorRepository`) sends at most `CoAuthorDeck.MAX_NOTES_SENT` notes as plain text; "Find duplicates" is on-device (`DuplicateFinder`). Keep the disclosure string in sync with what is sent.
- Study-time AI lives in `StudyAssistViewModel` (separate from `StudyViewModel`) and only shows once the answer is revealed and a route exists. A complete Explain/Example answer is saved per note (`ai_answers`, `AiAnswerDao`) by `StudyAssistRepository.explain`; `Run(assist)` shows the saved one without a request, `Run(assist, regenerate = true)` (Regenerate, Try again) asks again. A rewrite of a cloze note must keep the same cloze numbers, or it can't be applied.

## Analytics and the optimizer (ADR 0007)

- Stats are SQL aggregates only (`StatsDao`, one row per day/deck/bucket), mapped by `StatsRepository` and combined in `ComputeRetentionStatsUseCase` (Analytics) and `GetRetentionOverviewUseCase` (Decks tiles, retention health). Don't load cards or reviews to compute a metric.
- SQLite has no `pow`: retrievability comes from per-deck buckets of `elapsed days / stability`, evaluated once per bucket with `Fsrs.retrievability(ratio, 1.0)`.
- Metric definitions (true retention, mature ≥ 21 days stability, time saved vs. daily review, leech ≥ 8 lapses) are in the ADR; keep the UI strings consistent with them.
- `FsrsOptimizer` (`:core:scheduler/optimizer`) ports py-fsrs 6.3.2's optimizer with hand-derived forward-mode gradients. If you change its math, rerun `core/scheduler/fixtures/make_optimizer_fixtures.py` (needs `pip install "fsrs[optimizer]==6.3.2"`) and `FsrsOptimizerTest`; `gradientMatchesFiniteDifferences` checks derivatives on their own.
- Fitted weights live in `UserSettings.fsrsWeights` (DataStore). `OptimizeFsrsWorker` → `FsrsOptimization` applies them only if they lower the loss. Always build FSRS parameters with `StudyScheduler.parameters(settings)` so the fitted weights are used.

## Tests

- Fakes for every repository are in `:core:testing/repository`. ViewModel tests build real use cases on top of them. Create ViewModels lazily or inside the test, after `MainDispatcherRule` has set `Dispatchers.Main`.
- In Android modules use `org.junit.Test` (`kotlin.test.Test` doesn't resolve there); `kotlin.test` assertions are fine.
- Compose UI tests run on Robolectric in `androidHostTest` (features, `:shell`) and `src/test` (`:app`), so the exit check covers them. On the desktop, `:desktop`'s `DesktopAppTest` drives the whole app with `runComposeUiTest` on the real desktop graph and a temporary data directory (it sets `Dispatchers.Main` to a test dispatcher, because navigation insists on the main thread), and every `commonTest` ViewModel test also runs as a `desktopTest`. App tests run on `TestMnemoApplication` (`@Config(application = …)`, also the default in `robolectric.properties`) with `testStorageModule` (in-memory DB, per-test DataStore file) and a phone-sized `@Config(qualifiers = …)`; Robolectric's default screen is too small for off-screen clicks.
- Known Robolectric limit: a text field inside a Compose `AlertDialog` never lets the test go idle. Test dialog logic through the ViewModel instead.

## UI

- Jetpack Compose + Material 3. Wrap screens in `MnemoTheme` (`:core:designsystem`, `theme/Theme.kt`). The brand palette from `docs/design/` is the default. Dynamic color is opt-in (`dynamicColor = true`).
- M3 slots cover colors, shapes, and most type. Extra tokens come from `MnemoTheme.typography` (`studyPrompt`, `metricLg`, `metricSm` …) and `MnemoTheme.spacing`. Fonts (Newsreader, Hanken Grotesk, JetBrains Mono) are bundled in `core/designsystem/src/commonMain/composeResources/font` and loaded in `MnemoTheme` (composable `Font(Res.font…)`), so a `fontFamily` of your own comes from `MnemoTheme.fonts`, never a global. Every module's strings are in its `composeResources/values/strings.xml` (`stringResource(Res.string.x)`, with one `import <package>.resources.x` per string: the accessors are extensions). Formats must be positional (`%1$s`, `%1$d`; `%02d` and other flags are not supported: format the number in code), apostrophes are plain `'`, and outside composition use the suspend `getString` / `getPluralString`; a string passed around is a `StringResource`. Shared wording must not assume a phone ("this device"); hide what a platform lacks through `PlatformCapabilities`.
- Launcher icon layers, the splash icon and `mnemo_logo` are generated from the logo by `docs/release/assets/generate_icon_drawables.py` (see `docs/release/assets/README.md`): edit the script and rerun it, not the XML. `MainActivity` launches with `Theme.Mnemo.Starting` (core-splashscreen); use `MnemoLogo` for the logo in Compose.
- Use `MnemoIcons`, not `Icons.*`, and the components in `core/designsystem/.../component/`. Keep the Roborazzi catalog test in sync when you add a component.
- **Insets**: the app runs edge-to-edge. On tab screens, `MnemoApp` (`:shell`) shows `MnemoTopBar`/`MnemoNavigationBar`, which pad themselves for the system bars, and the Scaffold uses `contentWindowInsets = WindowInsets(0)`. Tab screens just fill the padding they are given. Non-tab screens (like Settings) get the whole window and own a `Scaffold` + `MnemoTopBar` with a back button. The shell hides its bars for them.
- Feature screens follow the Route/Screen split described in ARCHITECTURE §4.1: a stateless `*Screen` with `@Preview`, and a `navigation/*Navigation.kt` exposing `NavGraphBuilder.xxxScreen()` and `NavController.navigateToXxx()`.
